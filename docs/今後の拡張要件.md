# 今後の拡張要件

作成日: 2026-05-27

このドキュメントは、X Bookmark Viewer の今後の拡張候補を整理するためのメモです。
現時点では実装タスクではなく、方向性・優先度・判断基準を残すことを目的とします。

## 基本方針

- X/Twitter の代替クライアントにはしない。
- 対象は「ブックマーク済みポストを静かに読む、探す、整理する」体験に絞る。
- X API の利用量を抑えるため、ローカルキャッシュを優先する。
- 書き込み操作は最小限にし、誤操作から戻せる UI を用意する。
- ローカル個人利用を前提に、外部サービス連携や公開機能は慎重に扱う。

## 優先度の目安

- P0: 現在の使い勝手や安全性に直結するもの。
- P1: ブックマーク閲覧体験を大きく改善するもの。
- P2: あると便利だが、運用や設計の検討が必要なもの。
- P3: 将来的な候補。現時点では実装しない前提で記録するもの。

## 現時点の優先対応順

2026-05-28 時点では、秘密情報の除外、OAuth エラー情報の抑制、外部翻訳の opt-in 化、DB バックアップ/復元手順などのセキュリティ基礎対応は v1.2.0 で一度入っている。
また v1.2.1 で、表示中の一覧がローカルキャッシュ由来か API 更新済みかの表示と、更新中/完了状態のフィードバックも入った。
そのため、次の優先度は「残っている安全性の穴を維持しつつ、読む・探す・見分ける体験を改善する」順に寄せる。

1. 検索機能。
2. 視認性改善。色、フォントサイズ、文字ウェイト、カード内の情報階層を整理する。
3. スレッド頭や続きありの判別表示。
4. タグ、リスト、コレクションなどのローカル整理機能。
5. トップへ戻る、前/次カード移動などのナビゲーション操作。
6. 横長/縦長に応じたカード幅と左右余白の調整。
7. 削除/Undo、DB 復旧、エクスポートなど安全性に関わる機能の継続改善。
8. AI、Obsidian、Notion などの外部連携。

## セキュリティ・ロールバック優先対応

実装順は、秘密情報の漏えい、X 側への書き込み副作用、DB に蓄積される個人データ、実ソースへの影響範囲を基準に決める。
v1.2.0 で基礎対応済みの項目はあるが、機能追加時の判断基準として引き続き残す。
新機能を追加するときは「漏れない」「戻せる」「消せる」「影響範囲を切れる」状態を維持する。

### 最優先で潰すもの

- `.env`、`.env.local`、`.env.production` などの秘密情報ファイルを Git 管理から除外し続ける。
- SQLite の `data/`、`.next/standalone/data/`、`.next/standalone/.env` を GitHub、zip、手動アップロードに含めない。
- `X_CLIENT_SECRET`、`TOKEN_ENCRYPTION_KEY`、OAuth access token / refresh token がログ、URL、エラー理由、README、スクリーンショットに出ないようにする。
- OAuth callback の `error` パラメータに外部 API の詳細エラーや秘密情報を載せない。
- 翻訳など外部サービスへ本文を送る機能は、既定で無効化し、明示 opt-in にする。
- ブックマーク削除など X 側へ書き込む操作は、確認、Undo、失敗時のローカル状態復旧を優先する。

### DB 蓄積データの扱い

- DB にはブックマーク本文、投稿者情報、メディア URL、メモ、API 使用履歴、暗号化済みトークンが残る前提で扱う。
- DB バックアップ、エクスポート、インポート、AI 連携、外部サービス連携はすべて「個人データの持ち出し」扱いにする。
- DB スキーマ変更は、破壊的変更を避け、追加カラム/追加テーブルを優先する。
- 既存データの移行が必要な機能は、事前バックアップ手順、失敗時の復旧手順、再実行可能性を確認してから実装する。
- 削除済み、取得失敗、メモ、タグ、既読などのローカル状態は X 側の状態と混同しない名前で保存する。

### 実ソースへの影響切り出し

- セキュリティ系の共通処理は `lib/` に閉じ込め、UI コンポーネントへ秘密情報や生トークンを渡さない。
- DB 書き込み、X API 書き込み、ローカル UI 状態更新を同じ関数に詰め込みすぎない。
- 新機能は「読み取り専用」「ローカル DB だけ変更」「X API に書き込む」のどれかを明確に分類する。
- ロールバックしやすいように、DB マイグレーション、API ルート、UI 変更をできるだけ別 PR/別コミットに分ける。
- 外部連携や AI 要約は、まずエクスポート形式の整備を優先し、アプリ本体から直接送信する実装は後回しにする。

### セキュリティ観点の優先対応順

1. `.gitignore` と配布対象の見直し。v1.2.0 で基礎対応済み。今後は追加ファイルのたびに確認する。
2. OAuth / エラー表示から秘密情報が漏れないようにする。v1.2.0 で基礎対応済み。今後はログ追加時に確認する。
3. DB バックアップと復旧手順を README に明記する。v1.2.0 で基礎対応済み。実運用で足りない手順があれば追記する。
4. ブックマーク削除のローカル状態と X 側状態のずれを扱いやすくする。
5. DB スキーマ変更方針を決め、追加型の変更に寄せる。
6. エクスポート/インポートは個人データ持ち出し前提の警告と対象範囲選択を用意する。
7. AI / Obsidian / Notion などの外部連携は、送信データ、保存先、取り消し可否を仕様化してから検討する。

## 現時点で感じている課題

実際に触っていて「うーん」と感じている点。
機能不足だけでなく、読むための視認性・情報の強弱に関する課題が大きい。

- ダークモードメインとはいえ、色味が揃いすぎていて要素の区別がつきづらい。
- 検索機能がないため、ローカルに残したブックマークを探し直しにくい。
- タグ、リスト、コレクションのような整理単位がほしい。
- ローカルにデータを残していることを、検索や分類にもっと活かしたい。
- スレッド化しているポストかどうかが分かりづらい。
- このツール上でスレッドを全部まとめる必要はないが、「これはスレッドの頭」という目印はほしい。
- 一覧を読んでいる途中で、トップへ戻る操作がほしい。
- 1つ前/次のブックマークへ送る操作を、スクロールだけに頼らず使いたい。
- 1ツイート表示の横幅や左右余白を、ブラウザの縦横比に追随させたい。
- 横長画面と縦長画面で、それぞれ読みやすい表示幅に固定したい。
- 名前と本文のフォントサイズが近く、カード内の情報階層が分かりづらい。
- 全体的にフォントサイズもフォント種別も揃いすぎていて、目が滑る。

### UI 改善の方向性

- 色だけでなく、余白、文字サイズ、文字ウェイト、区切り線、背景差で情報の階層を作る。
- 投稿者名、ハンドル、本文、日付、操作ボタン、メモの見た目を明確に分ける。
- ダークモードのままでも、カード、本文、メタ情報、操作領域のコントラスト差を増やす。
- 装飾を増やすより、読む順番が自然に分かることを優先する。

## P0: 残っている安定性・安全性

### キャッシュと同期状態の可視化

- 表示中の一覧がローカルキャッシュ由来か、API から更新済みかは v1.2.1 で基礎対応済み。
- 更新実行中と完了状態のフィードバックは v1.2.1 で基礎対応済み。
- 最終取得日時を画面上で確認できるようにする。
- API 制限、認証切れ、課金エラーの状態をより具体的に表示する。

### 削除操作の安全性

- ブックマーク解除前の確認表示を分かりやすくする。
- Undo 可能な時間や状態を明示する。
- API 失敗時に、ローカル表示と実際のブックマーク状態がずれないようにする。

### データ保全

- SQLite データのバックアップ方法は v1.2.0 で基礎対応済み。実運用で不足があれば追記する。
- Docker volume を消すと失われる情報を README と仕様書で明確にし続ける。
- トークン再生成や暗号化キー変更時の注意点をまとめる。

## P1: 読む・探す体験

### ローカル検索

- 保存済みポスト本文を対象に検索できるようにする。
- 投稿者名、ユーザー ID、URL、メモを検索対象に含める。
- API を呼ばず、まずは SQLite 内のデータだけで完結させる。
- ローカルに保存したデータを活かし、過去に見たブックマークを再発見できる体験にする。
- 検索欄は常に見つけやすい場所に置く。

### フィルタ

- 画像あり、動画あり、引用あり、メモありで絞り込めるようにする。
- 投稿者ごとの絞り込みをできるようにする。
- ブックマーク解除済み、取得失敗、本文欠落などの状態で絞り込めるようにする。

### 並び替え

- ブックマーク取得順、投稿日時順で切り替えられるようにする。
- 将来的にはメモ更新日時順も検討する。

### 長文・スレッド表示

- 長文ポストやスレッド取得の成功/失敗状態をカード上で分かるようにする。
- スレッド展開済みの本文と元ポスト本文の扱いを整理する。
- API 取得と Web fallback の優先順位、保存範囲、再取得条件を明文化する。
- スレッドの全体をこのツール内でまとめ直すことは必須ではない。
- 「これはスレッドの頭」「この投稿には続きがある可能性が高い」という状態をカード上で分かりやすく表示する。
- スレッド判定に必要な API 情報、引用/返信/会話 ID の扱いを確認する。

## P1: 整理機能

### ローカルメモの強化

- メモありのカードを見つけやすくする。
- メモ編集時の保存状態を明示する。
- メモ本文も検索対象にする。

### タグ

- ローカル専用タグを付けられるようにする。
- タグは X 側には送信しない。
- タグ名の変更、削除、統合が必要になるため、最初から管理 UI の要否を検討する。
- タグ以外に、リストやコレクションのような整理単位も候補にする。
- 最初は「複数タグ」か「単一リスト」かを決めすぎず、ローカル整理として何が自然かを検討する。

### 既読・あとで読む状態

- ローカル専用の状態として、既読/未読、あとで読む、アーカイブを検討する。
- X のブックマーク状態とは別物として扱う。
- 状態が増えすぎるとアプリの目的がぶれるため、最小限にする。

### 完全非表示フラグ

- 折りたたみ表示は v1.3.1 で基礎対応済み。
- 完全に非表示にする場合は、検索、フィルタ、復帰手段を用意しないと戻せなくなるため慎重に扱う。
- X 側のブックマーク状態には触らず、ローカル DB 専用の表示状態として扱う。

## P2: エクスポート・バックアップ

### エクスポート

- JSON でローカルデータを出力できるようにする。
- Markdown 出力は、必要性が高まった場合に検討する。
- 画像や動画の実体保存は、容量・権利・再配布リスクがあるため慎重に扱う。

### インポート

- バックアップ JSON から復元できるようにする。
- 既存データとの重複、削除済み状態、メモやタグの衝突ルールを決める。

### DB メンテナンス

- 古い取得失敗レコードの再取得。
- 不要なキャッシュの削除。
- DB サイズや件数の簡易表示。

## P2: UI/UX

### 視認性

- 投稿者名と本文のフォントサイズ、ウェイト、色を明確に分ける。
- ハンドル、日付、API 状態、操作ボタンなどのメタ情報は本文より控えめにする。
- 本文は読みやすさを優先し、行間と最大幅を調整する。
- カード内で「誰が」「何を言っていて」「どう操作できるか」が一目で分かるようにする。

### 色とコントラスト

- ダークモードの色味が揃いすぎないよう、背景、カード、境界、テキスト、リンク、警告の役割色を整理する。
- 同じ青/グレー系に寄りすぎないよう、アクセント色は用途を絞って使う。
- ホバー、選択中、エラー、成功、同期中などの状態差を色だけに頼らず表現する。

### 表示密度

- 通常表示とコンパクト表示を切り替えられるようにする。
- メディアを大きく見るモードと、本文を素早く読むモードを分ける。

### 表示幅と余白

- 1ツイートのカード幅は、単純な固定幅だけでなくブラウザの縦横比を見て調整する。
- 横長画面では左右余白を広めに取り、本文幅が広がりすぎないようにする。
- 縦長画面では左右余白を抑え、カード本文に十分な表示領域を確保する。
- 画面サイズではなく、横長/縦長の見え方に合わせて読みやすい幅を決める。
- 本文、画像、操作ボタンの配置が表示幅の変化で崩れないようにする。

### キーボード操作

- 次/前のカード移動。
- 画像モーダルを Esc で閉じる。
- 検索欄へのフォーカスショートカット。

### ナビゲーション操作

- 一覧のトップへ戻るボタンを用意する。
- 表示中のカードから1つ前/次のカードへ移動するボタンを用意する。
- ボタンは読んでいる位置から使いやすい場所に置く。
- キーボード操作とボタン操作の挙動をそろえる。

### モバイル対応

- 現時点では PC ブラウザ優先。
- スマートフォン対応は、閲覧だけなら P2 として検討する。
- ブックマーク解除などの書き込み操作は、誤操作防止を優先する。

## P3: 外部連携

### Obsidian / Notion 連携

- 直接連携は現時点では実装しない。
- まずはエクスポート形式を整える。
- 外部サービスの認証や同期を持ち込むと、ローカル個人利用のシンプルさが損なわれる可能性がある。

### AI 要約

- 現時点では実装しない。
- ローカルキャッシュの本文を対象に、任意実行の補助機能としてなら検討余地あり。
- API キー管理、送信データの扱い、コスト表示が必要。

### 自動分類

- タグや検索が整ってから検討する。
- 自動処理よりも、ユーザーが理解できるローカル整理を優先する。

## 明示的にやらないこと

- タイムライン閲覧。
- 通知閲覧。
- DM 閲覧。
- 投稿、返信、いいね、リポスト。
- おすすめ表示。
- プロフィール巡回を主目的にした機能。
- X の完全アーカイブ取得。
- 公開サービス化。
- 複数ユーザー前提の共有機能。

## 未決事項

- タグ、既読、アーカイブをすべて持つべきか。
- 検索インデックスを SQLite の LIKE で始めるか、FTS を使うか。
- エクスポート形式を JSON のみにするか、Markdown も早めに用意するか。
- 画像や動画のキャッシュ実体を保存するか、URL 参照のみにするか。
- API 使用量の予算表示を、どこまで厳密にするか。

## 実装に進む前の確認観点

- X API の利用量が増えすぎないか。
- ローカル DB のスキーマ変更が必要か。
- 既存データのマイグレーションが必要か。
- 誤って X 側に書き込む操作が増えないか。
- README、仕様書、CHANGELOG のどこを更新するか。

## 実装済み項目

### v1.3.1 - 2026-05-29

- ブックマークカードをローカル状態として折りたためるようにした。
- 折りたたみ状態はブラウザを閉じても残るよう、`bookmark_view_states` に `tweet_id` ごとに保存するようにした。
- 折りたたみ時の表示は、該当アカウント、本文1行目、開くボタンだけにした。
- メモ、ブックマーク解除、全文取得、翻訳などの操作は通常表示の中に畳み込んだ。

### v1.2.1 - 2026-05-28

- 表示中の一覧がローカルキャッシュ由来か、API から更新済みかを分かるようにした。
- 更新実行中と完了が分かるように、更新ボタンへスピナー/チェックマーク、ヘッダーへ進行バーを表示した。
- ローカル開発時はポート 8080 を維持する方針をドキュメント化した。

### v1.2.0 - 2026-05-28

- `.env*` を Git 管理から除外し、`.env.example` は追跡対象として維持した。
- OAuth 失敗時の詳細情報を URL やサーバーログへ出しすぎないようにした。
- 外部翻訳を既定で無効化し、`ENABLE_EXTERNAL_TRANSLATION=1` の明示 opt-in にした。
- ローカルメモ保存時に認証を要求するようにした。
- ブックマーク削除時もローカルメモを保持し、Undo/復旧時の影響を小さくした。
- DB バックアップ/復元スクリプトを追加した。
- セキュリティ、ロールバック、DB 取り扱い、運用手順をドキュメント化した。

### v1.1.1 - 2026-05-27

- X 動画メディアを `/api/media/video` 経由でプロキシし、ブックマーク内動画を再生しやすくした。
- 動画の再生オーバーレイと再生失敗時のメッセージを追加した。

### v1.1.0 - 2026-05-27

- 投稿者を `Name (@handle)` の形式でカード内に表示した。
- 投稿者/日付リンクに hover 色と下線を追加し、クリック可能であることを分かりやすくした。

### v1.0.0 - 2026-05-27

- ローカル X Bookmark Viewer として v1.0.0 に到達した。
- 初期表示で SQLite キャッシュを優先し、追加読み込みでも API より先にキャッシュを使うようにした。
- ブックマークごとのローカルメモを追加した。
- アプリバージョンと X API の月額概算コストを表示した。
- ポスト本文内 URL のリンク化と、カード内動画表示を追加した。
- ローカルキャッシュ、予算設定、Docker volume の挙動をドキュメント化した。
