# 運用手順

このアプリはローカル個人利用を前提にしているが、SQLite にはブックマーク本文、投稿者情報、メディア URL、ローカルメモ、API 使用履歴、暗号化済み OAuth トークンが残る。
GitHub、zip、スクリーンショット、外部連携に含めるデータは慎重に扱う。

## GitHub に含めないもの

- `.env*`
- `data/`
- `.next/`
- `node_modules/`
- `tsconfig.tsbuildinfo`

`.env.example` だけは共有用のテンプレートとして Git 管理する。

## DB バックアップ

ローカル実行時:

```bash
npm run db:backup
```

Docker Compose 実行時:

```bash
docker compose exec app npm run db:backup
```

既定では `DATA_DIR` 配下の `backups/` に `app-YYYY-MM-DD...sqlite` を作る。
バックアップファイルも個人データなので、公開リポジトリや共有ストレージに置かない。

## DB 復元

復元前にアプリを止める。

```bash
docker compose down
```

ローカル実行時:

```bash
npm run db:restore -- data/backups/app-YYYY-MM-DD.sqlite
```

復元時は現在の `app.sqlite` を `app.before-restore-YYYY-MM-DD...sqlite` として退避してから置き換える。
`app.sqlite-wal` と `app.sqlite-shm` は復元前に削除する。

## Docker volume 削除時の注意

以下を実行すると DB も消える。

```bash
docker compose down -v
```

ログイン情報、ローカルメモ、キャッシュ、API 使用履歴を残したい場合は、先に DB バックアップを取る。

## TOKEN_ENCRYPTION_KEY の注意

`TOKEN_ENCRYPTION_KEY` を変更すると、既存 DB 内の暗号化済みトークンを復号できなくなる。
通常運用では、初回設定後に変更しない。

変更が必要な場合は、先に DB バックアップを取る。

```bash
npm run db:backup
```

変更後に保存済みログインを引き継ぐことはできないため、再ログインできる状態で作業する。
ローカルメモやキャッシュを残したい場合は、DB 全体を削除せず、元のキーに戻せるように `.env` の変更履歴を控えておく。

キー変更後に認証エラーや復号エラーが出た場合の選択肢:

- 元の `TOKEN_ENCRYPTION_KEY` に戻して再起動する。
- DB バックアップから復元する。
- ローカルメモやキャッシュを失ってもよい場合だけ、`docker compose down -v` で volume を削除して再ログインする。

`X_CLIENT_SECRET` を再生成した場合も、X Developer Portal 側の値と `.env` の値をそろえ、コンテナを再作成してから再ログインする。

## 外部翻訳の注意

翻訳機能はポスト本文を外部翻訳サービスへ送るため、既定では無効にする。
使う場合だけ `.env` で明示的に有効化する。

```env
ENABLE_EXTERNAL_TRANSLATION=1
```

公開したくない本文、メモ、個人情報を含む可能性があるデータは、外部翻訳に送らない前提で扱う。

## ロールバック方針

- X API に書き込む操作とローカル DB 更新は分ける。
- DB スキーマ変更は追加テーブル/追加カラムを優先する。
- 破壊的な DB 変更を入れる前に `npm run db:backup` を実行する。
- 外部連携、AI 要約、エクスポートは個人データ持ち出しとして扱い、送信対象を明示してから実装する。
